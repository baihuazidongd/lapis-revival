# 宝石幻想 ラピスリライツ 単機化復活プロジェクト（Lapis Re:LiGHTs）

既にサービスが終了した Unity モバイルゲーム『宝石幻想：光芒重现』（`com.klab.lapis` 1.5.0、KLab / KADOKAWA、2022-10-31 サーバー終了）の
**ローカル互換と単機化（オフライン化）の研究**。目標は、本来オンライン接続が必須だったクライアントを、インターネットに繋がない 1 台の
マシンで完全にメイン画面まで入り、ステージ戦闘を突き抜け、ショップとアリーナを使い、UI とテキストを簡体字中国語に変換すること。

このリポジトリには**コード・ツール・ドキュメントのみ**を置き、ゲームコンテンツは一切置きません。すでに自身でクライアントとアセットを
入手済みの人向けの再現手順であり、インストールパッケージでも公式サーバーでもありません。

## 現時点で何ができるか（Android 12 タブレット 2000x3200 と x86_64 AVD で実機検証）

| 本来は通信が必要だった部分 | 状態 | 判定基準（その場で再実行可能） |
| --- | --- | --- |
| ログイン / ハンドシェイク / メイン画面 | 使用可 | コールド起動でメインルームに入り、`LuaException` なし |
| ステージ戦闘（メインストーリー） | 最初から最後まで攻略可 | ダウンロード→タイトルカード→会話→戦闘→報酬配布→次の幕、1,566 ステージすべて星 3 |
| ショップ（購買部） | 開ける・購入できる・永続化される | `P120` が完全な UI を返す；`P121 goods=100012 x1 bought=1`；残高は `CostValue` で減算 |
| アリーナ | 使用可 | `P200` で出撃、`P204` で精算採点、勝利 +20 / 敗北 +5 を次回ちゃんと読み取れる |
| ガチャ（召喚） | 使用可 | `P1024` でガチャプール表示、配られたカードがセーブデータに入る |
| ホーム 3D 看板娘 / 部室「交流」 | 使用可 | `SceneMainStage` のキャラは `PBGameInfo.currentTheme` + `P11.themes[].seats` 由来；席テーブルが空ならその枠は null GameObject |

| セーブデータ | 再起動・再インストールをまたいで生存 | `force-stop` と `adb install -r` の後も残高 / 所持品が変わらない |

## アーキテクチャを一言で

Lua を 1 行も変更せず、ゲームロジックの再署名もせず、**デバイスの上に偽のサーバーを置く**：

```
クライアント ──gRPC/HTTPS──> TlsProxy(127.0.0.1) ──> HttpFileServer / GrpcApi  (Java、APK に同梱してインストール)
                                              │
                       プロトコルスタブ ProtobufCore ────  28 のプロトコル分岐（P11/P120/P121/P132/P180..186/P200/P204/P1024…）
                       SharedPreferences セーブデータ ─┘  lapis_state.xml：wal_/itm_/goods_/stage_/pvp_score/av_bind_/mir_*
                       インポータ ImporterActivity ──  納品された import.zip をデバイス上のアセットツリーへ展開
```

- `stubapp/`：Android 側のサービススタブ（Java）。`ProtobufCore` がプロトコル番号ごとに protobuf レスポンスを組み立てる（schema は
  APK 内の `protocol.descriptor.bin` から取り、`DynamicMessage` でその場でメッセージを生成）、`Seed` は SHA-1 で同梱データベースを
  固定し、`HttpFileServer`/`TlsProxy` はクライアントのドメインを `127.0.0.1` へ向ける。
- `tools/`：上記のデータを生成するスクリプト（パッケージ単位のフラグ反転、状態生成、データベース書き換え、アセットツリーの圧縮、配信、検証）。
- `manifests/`：期待ダイジェストのマニフェスト。ゲームコンテンツはここに無く、受け取る人が自分の手元のアセットで照合する。

## ビルドとインストール（ゲームデータは含まれず、クライアントとアセットは各自で入手）

```bash
export KS_PASS=<自分自身の keystore のパスワード> SERIAL=<adb devices に表示されるシリアル番号>
NO_INSTALL=1 PKG=cn bash tools/rebuild_relay.sh   # サービススタブ -> dex -> apktool -> zipalign -> apksigner
python tools/make_tree_zip.py                     # 7 GB のアセットツリー（端末一覧 + 上書き元 + SoundBank 補完）
bash tools/provision_files.sh                     # 配信
bash tools/delivery_gate.sh                       # 実機受け入れ：コールド起動 + 画面ごとのプロトコル番号判定
```

完全な順序、各ステップの判定基準、4 つのパッケージ単位フラグ反転がなぜ `javac` より前でなければならないか、sidecar がなぜ `.bnk` は 40 バイトで
`.bdl` は 41 バイトなのか、`errno=1455` の 2 つの原因、そして未解決項目：**`docs/BUILD.md` 参照**。

## このリポジトリに意図的に含めていないもの

- `.bdl` / `.assetbundle` / 音声 / 画像 / 動画 / メインデータベース / 言語テーブルの中身は一切；
- リバースエンジニアリングで得たクライアントの Lua、IL2CPP ダンプ、smali；
- ビルド成果物（約 242 MB の APK、約 7 GB のツリー）；GitHub でもこの規模は置けない；
- 秘密鍵、keystore、パスワード、アカウント、端末シリアル番号、セーブデータ。

理由は `NOTICE.md` 参照：ゲームコンテンツの著作権は KLab / KADOKAWA / 盛趣 に帰属し、本リポジトリには自分で書いたコードと導出過程のみを残す。

## 法と倫理の境界

いまも有効な課金や不正コピー対策を回避しない。すべてのリクエストは `127.0.0.1` に収束させる；クラッシュ報告チャネルは元クライアントの挙動で、変更していない。
