# 引き継ぎドキュメント：再現、現状、そして引き継ぎ手が最初にやるべきこと

このドキュメントは**あなたがこのプロジェクトの履歴を何も知らない**ことを前提に書いています。4 つの質問に答えます：どの入力が
必要か、ゼロからホーム画面までどうたどり着くか、今どこまでできているか、そしてどの罠は実測ですでに閉じられたか（もう二度と歩かないこと）。
具体的なコマンドと判定基準は `docs/BUILD.md`、方法論と失敗事例は `docs/TECHNIQUES.md` にあります。

---

## 0. リポジトリに無いもの、そしてあなたが必要とする入力

このリポジトリにあるのは**自作コード、スクリプト、ドキュメントだけ**です。オリジナルクライアントとそのすべてのアセットは入っておらず、git にも入りません：
ゲーム内容の著作権は KLab / KADOKAWA / 盛趣 にあり、GitHub の単一ファイル上限（100 MB）に 7 GB のアセットツリーは入りきらないからです。
したがって再現の前提は、これらのファイルをあなた自身がすでに所持していること（このプロジェクトは 2022 年のサービス停止前の公式アーカイブから作られました）。

| 入力 | どのステップで使うか | 検証 |
| --- | --- | --- |
| 公式クライアント `com.klab.lapis` 1.5.0 の APK（99,757,060 B、arm64-v8a + armeabi-v7a、`libklbsqlite3.so` を内包） | `apktool d` で `game_decoded/` を構築；全体ビルドの土台 | `manifests/required-inputs.tsv` |
| `Lapis-AssetBundles-20221022.7z`（4,229,156,448 B） | ホストのアセットミラーを展開 → `make_tree_zip.py` の本体 | 同上 |
| `Lapis-MasterData-20221022.7z`（1,799,924 B） | `master_data.db` / `master_data_lang.db` を展開：`Seed` の pin、`make_state`/`make_mirror`/`make_shopgoods` の入力 | 同上 |
| `Lapis-SoundBanks-20221022.7z`（1,732,452,189 B） | SoundBank 補完パート（デバイス側は原本 129/1,021 個しかなかった） | 同上 |
| `Lapis-manifests-20221201.7z`（1,053,953,620 B） | 上流のマニフェスト / バージョン記録。デバイスが実際に読むエントリの確定に使う | 同上 |
| 実機または AVD で数えた**デバイス一覧** | `make_tree_zip.py` の `DEVICE_LIST`（飾りではない、BUILD.md §3 参照） | 各自で用意 |

これは**非常に踏みやすい罠**が一つあります：手元に「フルパッケージのチャネル版 APK」（約 1.78 GB、`.bdl` を直接内包、ABI は
armeabi-v7a/x86 のみ）があっても、**それをビルドの土台にしないでください**。それは arm64 を含まず、我々がデコードしたあの一份でも
ありません；それで組んだパッケージは 64 ビットデバイスにインストールした時点で初めて問題が露呈します。判定基準は単純です：土台は `lib/arm64-v8a/libklbsqlite3.so` を含まなければならない。

ファイルを入手したら**まずダイジェストを突きけてから着手すること**：

```bash
sha1sum -c <(awk '$1!~/^#/ {print $3"  "$1}' manifests/required-inputs.tsv)
```

このステップは形骸化した手順ではありません。このプロジェクトでは 3 回の結論が覆りましたが、原因は毎回「入力が自分が思っていたあの一份ではなかった」ことです：
`font.bdl` をパス集合の比較で「同じ」と判定してしまった（実際は中身が違った）、JP ビルドに CN の言語テーブルの pin を入れてしまった、
そしてビルド失敗後に前ラウンドの古いパッケージを `adb install` してしまった。**ビルドはビット単位で再現可能ではありません**（zip のタイムスタンプがパッケージに入るため）、
同一性判定は**パッケージ内のアセット**と dex 中のリテラルでのみ行え、パッケージ全体のハッシュは比較できません。

## 1. ゼロからホーム画面まで（最短経路、各ステップの判定基準）

1. §0 の入力を揃えてダイジェストを照合する。
2. `apktool d -f -o game_decoded <公式 APK>`；自分の keystore を作り、`export KS_PASS=...`。
3. `docs/BUILD.md` §0 に従ってスクリプト中のプレースホルダパスを自分のディレクトリに書き換え、`export ADB_BIN=... SERIAL=...`。
4. 生成系スクリプト（`make_state` / `make_shopgoods` / `make_pvpreward` / `make_stageawards` /
   `make_mirror` / `gen_protocol_descriptor`）を回し、`stubapp/assets/` の 16 個のアセットを出力する。
   **判定基準**：`SeedHashTest` の合格（`Seed.java` 自身のハッシュコードで pin を突き合わせ、「1 バイト変えれば必ず失敗」のコントロールも含む）。
5. `NO_INSTALL=1 PKG=cn bash tools/rebuild_relay.sh`。
   **判定基準**：スクリプト内蔵の 6 ゲート——javac / d8 / アセット同期 / `SeedHashTest` / `pincheck`（ステージ時点と in-apk の 2 回）/
   Unity に焼き込まれたポート列に 18080 を含むこと。全緑で初めて APK が出力されます。
6. `python tools/make_tree_zip.py` → `tree_cn.zip`（約 7 GB / 12,718 エントリ / 1,040 bank）。
   **判定基準**：エントリ数とサイドカー長（`.bnk.hash` は改行なし 40 バイト、`.bdl.hash` は 41 バイト）。
7. インストール＋投入：`adb install -r` → `import.zip` として push → 一度起動 →
   **判定基準はこの 1 行だけ**：`logcat -d | grep "SEED tree installed"`。ファイルを数えないこと（インポートには数分かかり、途中で数えると必ず過小になります）。
8. コールドスタート受け入れ `bash tools/delivery_gate.sh`。
   **判定基準**：ホーム到達時、`P11 / P1024 / P120 / P60` は各ハンドラが応答し、`P132 / P1014 / P1028` は
   全ゼロのフォールバックで受け止められる（ログには出るが**専用ハンドラが無い**。§2 と §4 参照）。例外カウントは 0。
   この区別が重要：未マッピングのプロトコルは全ゼロで返るため、ページは開いても中身が空。
9. ページごとのスキャン `bash tools/sweep_cn.sh`。
   **判定基準**：各ページについて「このクリックが実際に発火したプロトコル番号＋クライアント例外回数」を記録し、スクリーンショットは記録しない。
10. JP パッケージ：`NO_INSTALL=1 PKG=jp bash tools/rebuild_relay.sh` ＋
    `python tools/make_tree_jp_from_cn.py`（同一ツリー＋ 632 件のパッケージ別差分を項目ごとに復元）、2 つのパッケージは同一デバイスに共存します。

**唯一の禁じ手：`adb shell pm clear` は絶対にやらないこと** —— 投入済みの 7 GB のツリーとセーブデータを同時に破壊し、復旧にはツリーの再プッシュが必要になります。

## 3. 引き継ぎ手が最初にやるべき 3 つのこと

### 3.1 裂け目の「挑戦」ボタン
`P180..P186` の一連は実測セマンティクス通りにサービス済み（`bout` = **使用済み回数**であと残り回数ではない、`round` = 到達済みの階、
週サイクルは**秒**使いで今週月曜 00:00 を取る）、パネルも実際に出ます。詰まっているのは「⚡5 挑戦」を押すと `P1021` のハートビートだけ出て `P42` が出ないこと。
**挑戦の前条件を調べに行ってください**、`P180` のフィールドをもう推測しないこと。現場では「カード保有」の編成エントリが無効状態（押しても反応なし）、
そして `P186`（ミラー編成）は実装済みなのに呼び出し手が誰もいません。もう 1 つの手がかり：パネルは推薦魔女力 99999999 と書くのに
`player.power` は 99999 で、戦力ゲートがボタンを直接飲み込んでいる可能性があります。

### 3.2 中国語フォントの本当の直し方
現在の簡体字中国語表示は**システムフォント**のフォールバックで持っています。我々の `font.bdl` は 13.8 MB、参照実装は 140 MB
（9 個の CJK フォントがそれぞれ Noto Sans CJK SC を内蔵、42,220 個のコードポイント）、そして我々が表示する簡体字中国語は 2,026 個のコードポイントを使います。
**直すべきは serialized file のバイト列**：UnityPy で `m_FontData` に値を入れて `save()` する道はすでに試して無効でした
（出力は 27.5 MB 増え、再読み込みすると元のサイズのまま——あれは解凍だっただけで置換ではなかった）。

### 3.3 残り中国語
ストーリーの会話は 631 個のストーリー `.bdl` の中にあり、`_language` 付きの JSON TextAsset です（46,277 行）。
読み取りの要点：`UnityPy` の `m_Script` だと `?` と読めてしまうので、`get_raw_data()` + `ensure_ascii` + `save('original')` を使うこと。
ほか残り 3 種類は**言語テーブルに存在しません**、テーブル上で探さないこと：Lua にハードコードされた文字列、UI アートに焼き込まれた文字、動画に焼き込まれた字幕。

## 4. 実測で閉じられたドア（もう絶対にたどらないこと）

| たどった道 | 結論 |
| --- | --- |
| Lua 末尾のダイジェストの解読 | 1,239 個のアセット × 340 通りの framing/ソルト、ヒットゼロ。**Lua のインプレース変更は計画しないこと**、すべてデータ側から変更する |
| クライアントコードを読むこと | `luaData` は解ける（実体は `select * from X` のローダ）、`scene`/`manager`/`ui` は解けない（印刷可能比率は約 0.15）。ただし**データ契約は読める**：`protocol.descriptor.bin` は単一の `FileDescriptorProto`（Set ではない）、407 個の message |
| 公式簡体字中国語パッケージを探すこと | JP 側の CDN と APK 成果物を洗い尽くした、**存在しない**；CN の残留は 61 行だけ |
| チャージページ | マスの内容は Google Play Billing のネイティブコールバック由来、5 個のメインタブは固定 prefab → データ側に手なし |
| UnityPy でのフォント差し替え | §3.2 参照、無効 |
| 用語衝突のバッチ掘り起こし | すべり窓と部分文字列の衝突で出るものは大半が偽陽性。信頼できる検証はただ 1 つ：**同一の出典が UI に複数の表記で現れること**；書き換えは必ず JP の原語で範囲を限定する |
| `pvp` / 掲示板の本物のサービス化 | 掲示板の HTTPS URL はクライアントに焼き込まれており、ポート導出は HTTP アセットの配信にしか有効ではない |
| root 化タブレット | bootloader 解除はデータを消去し、詰まっている項目を 1 つも解決しない → 実施せず |
| LDPlayer をテスト機にすること | x86 ホスト + arm のみのパッケージは翻訳が必須で、LDPlayer のゲストの中ではさらに**2 層目**の翻訳が重なる；AVD / 実機へ切り替え済み |
| AVD のタイミングで感触を判断すること | インポート解凍は AVD 441 s vs 実機 8 s（ディスクイメージは約 55 倍遅い）。**AVD のタイミングを実機のものと扱わないこと** |
| `wm size` から座標を推すこと | `wm size` が返すのは自然方向（1080x2400）、`input tap` が使うのは `rotation=1` の横画面空間で、互いに推定できません |
| 一括 `chmod` | shell が作った `0660` はアプリディレクトリ内だとアプリから読めません；アプリ自身が書いた `0660` は問題なし。一発で chmod しないこと |
| ホスト上の `device_files` ミラーを真値と見なすこと | 4,679 ファイルに対しては陳腐化しています；`adb pull` はアプリ自身の `0600` ファイルで中断もします |
| PNG のバイト数 / ピクセル差をページの判定基準にすること | どちらも不安定。ページの同一性 = プロトコル番号 |

## 5. 判定ツールボックス（このプロジェクトでの検証のやり方）

- **ページの同一性はプロトコル番号で判定**。未マッピングのプロトコルはゼロ埋めレスポンスを返され、ページはレンダリングされても中身は空のまま。
- **ハートビートを証拠に数えない**。`P9000` と `P1021` は 60 秒ごとに発火；「ログが動いた」ではクリックの有効を証明できません。
- **プロトコル対照表**（実測で得たもの、オラクルとして使う）：`P11` ホームは `themes[].seats` を含む / `P120` ショップ / `P121` 購入 /
  `P132` イベント / `P180..P186` 裂け目 / `P200` アリーナ出戦 / `P204` 決算 / `P1001` 利用規約同意 /
  `P1024` ガチャ / `P42` 戦闘開始。（`P132`/`P1014`/`P1028` は全ゼロのフォールバックのみで、ハンドラではない）
- **例外カウント**のほうがスクリーンショットより信頼できる：各ページに 1 回入り、`logcat -c` → 操作 → `logcat -d` で `LuaException` を数える。
  常時張り付きの `logcat -v time` は掛けないこと（単発スキャンで 2.1 GB 書いたことがある）。
- **1 デバイスに駆動者は 1 人**：2 つの駆動者が交互にクリックしても大きなエラーは出ず、「このページは開いたのにプロトコル無し」の偽結果を書くだけ。
  スクリプトは `mkdir` のアトミックロックでブロック；殺されたバックグラウンドタスクは生きた子プロセスを残すので、守護はロックでありタスクマネージャではない。
- **フレーム分類には自機で自ら採ったリファレンス画像が必要**。カットポイントはリファレンス画像の属性（デバイスごとに違う）であって、ゲームの属性ではない。
- **判定手段そのものを検証すること**：差値を報告するなら、まず同一対象を繰り返し測定したノイズフロアを出す；飽和した対照は証拠に数えない；
  守護のコントロール群は、ブロックされる入力を実際に自分で偽造できなければならない。常に 0 のカウンタも機能停止したセレクタも、音もなく通過します。

## 6. 成果物の形態（「完成品」とは何か）

```
game_relay_cn.apk    242,144,815 B   # CN パッケージ、薄い APK（アセットツリーを含まない）
game_relay_jp.apk    240,334,383 B   # JP パッケージ
tree_cn.zip        7,003,552,761 B   # 名前を import.zip に変えて投入
tree_jp.zip        7,002,068,161 B
```

指紋は `manifests/delivery-sha1.txt`（我々自身が計算したもの、「入ったのはどの版か」の確認用）。
納品物は 2 つだけ：**薄い APK ＋ `import.zip` 1 個**。セーブデータは単一の
`shared_prefs/lapis_state.xml`、キースペースは `wal_` / `itm_` / `goods_` / `stage_` / `av_bind_` / `mir_` / `pvp_score`；
`force-stop`、`adb install -r`、再起動を跨いで生き残り、`pm clear` / アンインストール / 署名変更で失効します。

## 7. 環境レベルで変わりやすいもの（マシンを跨ぐ再現で噛みついてくる）

- **ドライブ文字とディレクトリは平気でずれる**。このマシンは 2 週間で SDK と AVD を C: から E: へ、そこから D: へ移し、そのあと `D:` ボリューム全体が消滅した
  （C: に統合）。したがってドキュメント中の絶対パスはすべて**陳腐化済み**として扱い、先に `stat` してから使うこと；このリポジトリは一律にプレースホルダパスを使っています。
- **`errno=1455 ページファイルが小さすぎ` の成因は 2 つ**：ヘッドレス AVD が利用可能なコミットメモリを食べ尽くす（実測で qemu プロセス 26.5 GB private）、
  およびページファイルが膨張後に自ら縮まないこと（再起動が必要）。まず `Get-Process | Sort PrivateMemorySize64`、
  次に `Get-CimInstance Win32_PageFileUsage` で `AllocatedBaseSize` と `CurrentUsage` を比較；ディスクの状態はどちらも見ないこと。
- **adb の binary は 1 本だけ**：複数の adb が 5037 ポートの単一サーバを奪い合うと、症状は「デバイスが突然消える」と「USB が落ちる」になる。
- **AVD の起動の罠 3 つ**（必ず `emulator.exe` を経由、必ず `ANDROID_AVD_HOME` を付ける、必ず `ANDROID_SDK_ROOT` を付ける）
  と、毎回の新規起動で出るモーダルな `ImmersiveModeConfirmation`（実測した境界をクリックすること、`keyevent 4` は使わない）は `docs/BUILD.md` §8 にあります。
- **`wm density` を変えると「タップして再起動」のフローティングレイヤーが出る**ので、フレーム分類器が往復して振り回され、画面は実際にはとうにホーム——揺れたら直接フレームを見ること。
- **`keyevent 4`（戻るキー）はこのゲームのダイアログ入力を死なせます**、以降はフリーズしたクライアントをテストしているだけ。画面上の X をタップすること。

## 8. チートシート：新人が最も聞きやすいフィールドとルール

| 名称 | 実測セマンティクス |
| --- | --- |
| `PlayerInst` / `Newbie` | ゲートはこの 2 か所だけ：残高と保有物は `PlayerInst` から読む（支払い通貨は `diamondPay` に種別があり、`items[]` に 1 行差し込んでも惰性）；機能解放は `Newbie` から読む（レベル到達または該当ステージ通過済み） |
| `GoodsPrice` / `CostValue` | 前者はバッジ表示にすぎず、後者が `GetCost`・支払可能判定・実際の課金で使われるもの |
| `mir_*` 状態キー | `bout` = 使用済み回数（ローカル日単位でリセット）、`round` = 到達済みの階、`week` = 今週月曜 00:00 の**秒** |
| `themes[].seats` | ホーム画面の 3D キャラ（クラブルーム）の名簿ソース；席テーブルが空 → `SceneMainStage` 内は null GameObject |
| `.bdl.hash` / `.bnk.hash` | ローディングゲートであってメタデータではない：41 バイト vs 40 バイト（改行なし）。欠落も長さ違いも = アセットはロードされない |
| `EncryptKey` | マニフェスト中のこの int32 は**ヘッダの XOR**；非ゼロ + 平文 UnityFS ファイル = `Unable to read header from archive file` |
| `Unable to read header...` | 原因は 2 つでも症状は同じ：`EncryptKey` をゼロクリアしていないこと、そして元から 0 バイトだった上流 bundle。**まずサイズを見てからキーを見ること** |
| アセット欠落の現れ方 | SoundBank 欠落は**セクション全体が完全な無音**（エラーなし、ヒントなし、ログにも痕跡なし）；異常テキストが出るのは bundle 欠落のときだけ |
| `Seed` の自己修復 | 判定基準は**ファイルの存在**であってダイジェストの一致ではない。よって直した db をデバイスに乗せるには「ステージ + `cp`」を使うこと、APK を再コンパイルしないこと |
| サーバタイムスタンプ | `freshAt` / `EndTime` が過去時刻になった瞬間、`PageShop` は `OnEnter` の途中で自己消去する；オフラインでは一律 `0` を返す |
| traceback の行番号 | 必ずバイトコード行テーブル（`proto.debuginfo.addr_to_line_map`）で変換すること。Lua の行番号を直接読むと別の関数を指します |

## 9. このプロジェクトの境界（引き継ぐ前に読んでください）

**自分のデバイス上で既にサービスが停止している作品だけ**の相互運用研究とします：公式サービスの再開なし、ゲームコンテンツの配布なし、
いまも有効な課金または不正コピー防止の仕組みの回避なし。すべてのネットワークリクエストは `127.0.0.1` に収束；
クラッシュ報告チャネルはオリジナルクライアントの挙動で、変更なし。署名は我々自身の keystore（署名変更は元のセーブデータを失効させ、これはトレードオフ）。
リポジトリには鍵、パスワード、アカウント、デバイスシリアル、セーブデータ、そしてゲームコンテンツやデコンパイル成果物は一切置きません ——
この境界こそが本ドキュメントを公開していられる前提なので、引き継いだ後も守り続けてください。
